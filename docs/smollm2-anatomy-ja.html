SmolLM2-135M 解体図

PyTorch で自作したモデルに公開重みを読み込み、プロンプトの続きを生成させました。このページでは、何を作ったのか、ダウンロードしたファイルの中身、1つのプロンプトが文章になるまでを、実際の数値で図解します。

1 · ビルド

ビルドで作ったのは「回路」、重みはダウンロード

LLM は、構造（どの数値をどの順で掛け算・足し算するかという設計図）と、重み（その回路に入れる1億3451万個の定数）でできています。構造は model.py に自分で書き、重みは HuggingFace が約2兆トークンで学習済みのものを使いました。今回、学習はしていません。

重みの名前と自作部品の名前は1対1で対応していて、先頭の model. を外すだけでそのまま流し込めます。

回路が1か所でも違えば、意味のない文字列しか出ません。公式実装の transformers と比べて、次のとおり一致しました。

ダウンロードしたファイル

保存場所は ~/.cache/huggingface/hub/models--HuggingFaceTB--SmolLM2-135M/ です。合計272MBのうち、98.8%が重みの model.safetensors です。

safetensors 形式の中身

作りは単純で、「目次の長さ」「JSONの目次」「数値の生データ」の3つが並んでいるだけです。実行できるコードは入らないので安全で（名前の由来）、目次のオフセットを見れば必要な部分だけを直接読めます。

// JSON ヘッダの実物（先頭2件）
"model.embed_tokens.weight": {"dtype": "BF16", "shape": [49152, 576], "data_offsets": [0, 56623104]},
"model.layers.0.input_layernorm.weight": {"dtype": "BF16", "shape": [576], "data_offsets": [56623104, 56624256]}

BF16（bfloat16）は1個2バイトの浮動小数点数です。134,515,008個 × 2バイト ≈ 269MB で、ファイルサイズと一致します。読み込み時に float32（4バイト）へ変換しているので、メモリ上では約540MBになります。

1億3451万個の内訳

tokenizer.json（BPE）

語彙は49,152個、結合ルールは48,900個です。バイト単位から出発し、「Ġ+t → Ġt」のように、よく一緒に出る組を順にくっつけて単語片を作ります。Ġ は「直前にスペースがある」という印です。

3 · 推論

プロンプトが文章になるまで

今回の入力 "Once upon a time, in a small village," を例に、順を追って見ていきます。

①文字列をトークンIDにする

10トークンになりました。モデルが受け取るのはこの整数の列だけで、文字は一切見ていません。同じ語（Ġa、,）には同じIDが付きます。

Ġ は半角スペースです。この tokenizer は文字列をまずバイト列にし、256種類のバイトそれぞれを表示できる文字に置き換えます。スペース（0x20）のような見えないバイトは 256 ずらした文字に置き換えるので、0x20 + 0x100 = U+0120 の Ġ になります。スペースは次の単語の頭にくっつくので、同じ upon でも文頭と文中では別のトークンです。

upon25705
Ġupon1980
Once6403
ĠOnce4027

スペースを別トークンにせず単語側に含めると、トークン数が約半分で済みます。スペースの情報も失われないので、decode すると元の文字列に正確に戻ります。

②IDをベクトルにする（埋め込み）

各IDで埋め込み表（49,152行 × 576列）の行を引き、576個の数値にします。ここで 10×576 の行列ができます。「village」の行には、学習の結果として「村らしさ」が数値で染み込んでいます。

③30層の Decoder を通す

10×576 の行列が30層を順に通ります。各層は、ベクトルを置き換えるのではなく、2回の計算結果を足し込んでいきます（残差接続）。

RoPE は、位置の情報をベクトルの回転角として埋め込む仕組みです（θ = 100,000）。これで Attention が「何番目のトークンか」を区別できます。

④ベクトルを次の語の確率にする

最後の位置（,）の576次元ベクトルと、49,152語すべての埋め込みとの内積を取り（lm_head）、softmax で確率にします。実際の値の上位5つです。

⑤サイコロを振って1語選ぶ（サンプリング）

--temperature 0.8 で確率分布を少し尖らせ、--top-k 50 で上位50語以外を除いてから、確率どおりに1語を引きます。今回は24%の ' there' が出ました。--seed を変えると ' lived' が出て、別の話になります。temperature 0 にすると常に1位を選び、毎回同じ文章になります（verify.py の貪欲生成がこれです）。

⑥末尾に足して繰り返す（KV キャッシュ）

選んだ語を末尾に足して、①〜⑤をもう一度行います。ただし毎回全トークンを30層に通し直すと無駄なので、各層の Attention で計算した K と V を保存しておき、2回目以降は新しい1トークンだけを計算します。

⑦IDを文字列に戻す

出てきたIDの列を tokenizer で文字列に戻し、画面に出します。日本語などは1文字が複数トークンにまたがり、途中で切ると文字化けするので、毎回全体を decode して差分だけを表示しています。

4 · 分かること

ここから分かること

  • モデルがしているのは「次の1トークン当て」だけです。筋や一貫性は、それを繰り返した結果として現れているにすぎません。今回、フクロウのオリバーが「賢いフクロウ」に「オリバー、…」と話しかける矛盾が起きたのは、135Mという小ささの限界です。
  • これはベースモデルです。指示に従うよう追加学習した SmolLM2-135M-Instruct ではないので、質問しても答えず、文章の続きを書きます。
  • 日本語は苦手です。学習データの大半が英語なので語彙に日本語がほとんどなく、「こんにちは」の5文字は UTF-8 のバイト断片9個に分解されます。
